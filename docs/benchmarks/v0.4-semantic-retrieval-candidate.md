# ProjectAtlas v0.4 Semantic Retrieval Candidate Decision

## Outcome

ProjectAtlas v0.4 ships no semantic model or approximate-nearest-neighbor
runtime. Explicit `semantic` and `hybrid` search remain typed
`not-installed` capability failures, omitted mode remains lexical, and the
default binary keeps no model, ONNX, vector-index, or ANN dependency.

Three package-credible quantized candidates were deterministic and fast enough
on the measured Windows host, but all missed the retained quality and
process-memory gates. Adding lifecycle commands, vector persistence, or an ANN
backend for any of them would therefore add cost without an accepted
capability.

## Candidate Gate

The initial run was exploratory. Before the retained rerun, the following
candidate-admission decisions were frozen:

| Candidate | Top 1 (at least 80%) | MRR (at least 0.85) | Recall at 10 (1.00) | Peak working set (at most 384 MiB) | Decision |
| --- | ---: | ---: | ---: | ---: | --- |
| BGE small English v1.5 quantized | 11/17, 64.7% | 0.730 | 1.00 | 482.4 MiB | reject |
| Snowflake Arctic Embed XS quantized | 10/17, 58.8% | 0.721 | 1.00 | 646.1 MiB | reject |
| all-MiniLM-L6-v2 quantized | 11/17, 64.7% | 0.745 | 1.00 | 653.8 MiB | reject |

All three produced exactly repeatable vectors, embedded one changed row in
under 80 ms, answered the 17-query batch in under 110 ms, and used less than
100 MiB of model cache. Only the retained BGE run proceeded through the
license gate; its model and runtime are Apache-2.0. Required-platform proof was
not run after every candidate had already failed the Windows quality and memory
gates.

A code-specialized alternative,
`jinaai/jina-embeddings-v2-base-code`, was rejected before execution because
the model file selected by the current Rust library is 641,517,466 bytes, above
the package gate. Because no model passed, ProjectAtlas did not add or benchmark
an ANN dependency: exact scoring is sufficient for this bounded candidate set,
and an ANN index cannot repair embedding-quality misses.

## Retained Method and Corpus

- Source identity:
  `f892e99b32bc90f95970be3f1c730b065d9f5198`.
- Host: Windows 11 Pro 10.0.26200 x86-64, AMD Ryzen 7 3700X, 8 cores /
  16 logical processors, 32 GiB visible memory.
- Toolchain: Rust/Cargo 1.93.1,
  `x86_64-pc-windows-msvc`.
- Runtime: `fastembed` 5.17.3 with default features disabled and only
  Rustls Hugging Face plus ONNX Runtime binary acquisition enabled;
  `ort` 2.0.0-rc.12.
- Model: `Qdrant/bge-small-en-v1.5-onnx-Q`,
  `model_optimized.onnx`, 66,465,124 bytes,
  Apache-2.0,
  SHA-256
  `51f1bd0addd6e859e42c2c8021a5e5461385bb676a649f4b269aa445449f2431`.
- Inputs: 17 labeled 61-line source windows centered on exact owning
  definitions in the ProjectAtlas repository. Queries paraphrase the desired
  behavior and do not supply the owning symbol.
- Inference: 384-token maximum, four ONNX intra-operation threads, batches of
  eight, BGE retrieval query prefix, deterministic cosine ordering with source
  order as the tie break.
- Timings: 176 ms warm initialization, 1,768 ms for 17 source windows,
  105 ms for 17 queries, 1,708 ms for the repeat pass, and 79 ms for one changed
  row. The first cache-populating run initialized in 3,672 ms.
- The same corpus, inference limits, exact cosine ranking, and resource gates
  were rerun with `snowflake/snowflake-arctic-embed-xs:model_quantized.onnx`
  and `Xenova/all-MiniLM-L6-v2:model_quantized.onnx`. Dynamic quantized models
  used the runtime-selected batch size required by ONNX Runtime.
- Retained machine-readable queries, ranks, scores, timings, identities, and
  environment are in
  [`v0.4-semantic-retrieval-candidate.json`](v0.4-semantic-retrieval-candidate.json).

This is a bounded candidate-rejection gate, not a public comparative benchmark
or evidence that semantic retrieval is generally ineffective. A later candidate
may proceed only by rerunning a preregistered labeled corpus on every required
platform and then implementing the complete install, build, update, rollback,
disable, removal, containment, and generation-bound vector lifecycle.

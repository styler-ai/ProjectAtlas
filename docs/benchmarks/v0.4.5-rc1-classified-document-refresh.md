# v0.4.5-rc1 classified-document refresh measurement

This focused release-candidate measurement covers the schema-17 classified-document path on feature head `706ff246faa9c21e2bbafae88157b1646a599e2e`. The release-profile runtime SHA-256 is recorded in the [raw result](v0.4.5-rc1-classified-document-refresh.json). Its package identity is still `0.4.4` because the repository applies the `0.4.5-rc1` version only after feature integration; the same command must be rerun after that mechanical release bump.

The deterministic fixture contains 1,029 admitted files. One Markdown document owns the parser maximum of 256 static links into a 1,024-source Rust repository. The refresh changes only that document's heading while retaining all 256 resolved document relations.

## Result

| Metric | Full build | One-document refresh |
| --- | ---: | ---: |
| Admitted / parsed files | 1,029 | 1 |
| Wall time | 4.582199 s | 1.298109 s |
| Process-tree CPU time | 2.218750 s | 0.406250 s |
| Peak process-tree RSS | 43,196,416 B | 23,490,560 B |
| Process read transfer | 108,693,422 B | 43,045,738 B |
| Process write transfer | 464,093,936 B | 20,570,848 B |
| Persistent bytes after completion | 18,472,960 B | 18,968,576 B |
| Final WAL bytes | 0 | 0 |
| Serialized output | 924 B | 690 B |

The refresh's timeout-zero `BEGIN IMMEDIATE` sampler made 55 attempts. Four observed writer-busy samples produced a conservative maximum unavailable interval of 0.140419 seconds. The owning SQLite publication test traced 2,081 statements and 1,031 changed rows for the 256-link replacement; it retained all 256 relations. The document owns 1,036 durable rows before and after refresh, while repository graph totals and resolution counts remain unchanged. These are measured single-host Windows results, not cross-platform latency claims or a historical speedup claim.

All ten gates passed: the refresh parsed one file rather than the full 1,029-file repository, published the next generation, kept bounded output, retained the complete fanout, drained the WAL, and left no staging database.

## Reproduction

Build the release-profile candidate, then run:

```powershell
python -B docs/benchmarks/harness/classified_document_refresh.py --runtime target/release/projectatlas.exe
```

On Unix, pass `target/release/projectatlas`. The harness also runs the exact owning SQLite statement/row probe:

```text
cargo test --locked -p projectatlas-db repository_graph::tests::high_fanout_document_refresh_has_bounded_sql_and_changed_rows -- --exact --nocapture
```

# v0.4.5-rc1 classified-document refresh measurement

This focused release-candidate measurement covers the schema-17 classified-document path in the `0.4.5-rc1` working tree based on head `7f8ce515312bdddf359287ea1f34454fc369354a`. The exact release-profile runtime identity and SHA-256 are recorded in the [raw result](v0.4.5-rc1-classified-document-refresh.json).

The deterministic fixture contains 1,029 admitted files. One Markdown document owns the parser maximum of 256 static links into a 1,024-source Rust repository. The refresh changes only that document's heading while retaining all 256 resolved document relations.

## Result

| Metric | Full build | One-document refresh |
| --- | ---: | ---: |
| Admitted / parsed files | 1,029 | 1 |
| Wall time | 1.985722 s | 1.286415 s |
| Process-tree CPU time | 2.125000 s | 0.421875 s |
| Peak process-tree RSS | 39,841,792 B | 22,347,776 B |
| Process read transfer | 109,943,110 B | 42,922,858 B |
| Process write transfer | 465,307,308 B | 21,148,928 B |
| Persistent bytes after completion | 18,477,056 B | 18,972,672 B |
| Final WAL bytes | 0 | 0 |
| Serialized output | 924 B | 690 B |

The refresh's timeout-zero `BEGIN IMMEDIATE` sampler made 55 attempts. Four observed writer-busy samples produced a conservative maximum unavailable interval of 0.119459 seconds. The owning SQLite publication test traced 2,081 statements and 1,031 changed rows for the 256-link replacement; it retained all 256 relations. The document owns 1,036 durable rows before and after refresh, while repository graph totals and resolution counts remain unchanged. These are measured single-host Windows results, not cross-platform latency claims or a historical speedup claim.

All ten gates passed: the refresh parsed one file rather than the full 1,029-file repository, published the next generation, kept bounded output, retained the complete fanout, drained the WAL, and left no staging database.

## Reproduction

Build the release-profile candidate, then run:

```powershell
python -B docs/benchmarks/harness/classified_document_refresh.py --runtime target/release/projectatlas.exe
```

On Unix, pass `target/release/projectatlas`. The harness also runs the exact owning SQLite statement/row probe:

```text
cargo test --locked -p projectatlas-db repository_graph::tests::high_fanout_document_refresh_has_bounded_sql_and_changed_rows -- --exact --nocapture
```

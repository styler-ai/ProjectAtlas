# ProjectAtlas v0.4 Agent Navigation Evaluation

> **Task 7.3 forward-test result — not the release publication benchmark.**
> Task 7.6 must repeat the final v0.4, frozen v0.3.26, and no-ProjectAtlas arms
> after tasks 7.4 and 7.5 complete.

## Outcome

The packaged v0.4 ProjectAtlas skill and compatible MCP surface passed the
representative clean Git, saved-dirty Git, and non-Git agent tasks against
frozen v0.3.26.

Both versions answered every task correctly. V0.4 selected reviewed
purpose-plus-connection candidates, followed current saved source, proved the
public boundary, and returned exact slices with 24 MCP calls, zero
backtracks, and 15,295 emitted response bytes. V0.3.26 used 34 calls, recorded
two backtracks, issued three broad `atlas_files(include_content: true)` reads,
and emitted 19,094 bytes.

V0.4 therefore reduced:

- calls by 29.4%;
- emitted MCP evidence bytes by 19.9%;
- backtracks from two to zero; and
- cold context including the matching discovery and skill by 15.9%.

V0.4 discovery-plus-response bytes are 20.1% larger because issue #308 retains
the complete 40-tool compatibility inventory and its additive v0.4 schemas.
That regression is the explicit post-v0.4 issue #310 baseline, not a reason to
silently remove useful tools.

## Compatibility And MCP Decision

The candidate preserves:

- all 40 v0.3.26 tool names and descriptions;
- complete recursive legacy request schemas and omitted-argument defaults;
- legacy file-summary, session-brief, relation, warning, and error behavior;
- current summary, search, relation, and exact-slice strengths; and
- project-local and per-call project isolation.

The selected v0.4 additions are compact opt-ins and typed next-call guidance on
existing operations. The formal six-question composition evaluation rejects a
dedicated graph-question tool because even an impossible zero-byte source
payload could reduce the applicable route by only 6.1–8.1%, below the
preregistered 20% rule, while adding schema and orchestration overlap.

See the [formal composition report](v0.4-mcp-composition-evaluation.md),
[raw deterministic result](v0.4-mcp-composition-raw.json), and
[agent-trial result](v0.4-mcp-agent-trials.json).

## Earlier No-ProjectAtlas Checkpoint

The earlier task-5.8 checkpoint found that direct shell/source navigation was
far smaller on deliberately tiny 5-to-19-line fixtures. That is expected: a
tool inventory and index have fixed cost, while opening a handful of tiny files
does not. It is not used as the task-7.3 selected result because the v0.4
candidate and packaged skill changed afterward.

The release benchmark must determine the real break-even point rather than
turning a tiny-fixture loss or a large-repository expectation into a headline.

## Task 7.6 Gate

This forward test uses one stochastic trial per arm and fixture. It does not
claim a distribution, general latency, CPU, peak RSS, indexing/startup/storage
cost, or a no-ProjectAtlas break-even point.

Task 7.6 must rerun:

1. v0.4, frozen v0.3.26, and no ProjectAtlas under identical model, reasoning,
   permissions, prompts, fixture/corpus, and cache policy;
2. clean, saved-dirty, non-Git, small, medium, and pinned real-source
   large/huge work;
3. enough repeated stochastic trials to report medians and tail behavior;
4. correctness, calls, broad/full reads, backtracking, emitted and total
   navigation context, elapsed time, CPU, peak RSS, index/startup/storage cost,
   and break-even behavior; and
5. every failed or excluded run, raw machine-readable results, exact prompts,
   environment/candidate identities, rerun commands, and limitations.

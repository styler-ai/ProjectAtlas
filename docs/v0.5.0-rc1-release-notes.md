# ProjectAtlas v0.5.0-rc1

This release candidate brings the accepted v0.5 work together for installed-product acceptance. It is a prerelease; `v0.4.5` remains the stable installation default and GitHub Latest. Stable v0.5.0 promotion is a separate release decision.

## Included work

- Bounded PDF and DOCX navigation, built-in PHP parsing, and entrypoint analysis share the existing CLI and MCP surfaces.
- Worktree identity, graph publication, incremental refresh, and document navigation retain typed failure and recovery behavior.
- Installer and plugin updates preserve project state, verify exact runtime identity, and exercise repair, rollback, process ownership, and generated host configuration.
- Release admission verifies accepted child completion while allowing the release owner to perform publication and readback. Publication rechecks readiness immediately before creating a release or repairing its assets.

The [release architecture](v050-release-architecture.md) and [accepted scope](../openspec/changes/complete-v050-release-readiness/proposal.md#accepted-release-scope) describe the owning boundaries. Deferred npm delivery, shared released atlases, and later-version work are outside this candidate.

## Compatibility and packaging

The native release matrix covers Linux x64, Windows x64, macOS x64, and macOS arm64. Optional parser packs are available for Linux x64 and Windows x64; macOS uses the built-in capabilities. The [language support reference](language-support.md) records the generated capability contract.

The candidate pins the runtime, plugin manifests, host configuration, and parser-pack provenance to `0.5.0-rc1`. Accepted capability-set version 15 preserves version 14 language membership and strength while binding ProjectAtlas-owned parser provenance to this runtime version.

Existing v0.4.5 databases on Linux and macOS require explicit root recovery because
their legacy path metadata cannot establish native identity. Retain a compatible
database backup and verify the candidate archive checksum, then use that candidate
executable to run `root set <original-project-root> --transition adopt-legacy` and
retry the installer. This adopts the selected root and migrates the intact schema-19
database atomically while preserving authored state; ordinary opens never infer
this authority. See [installed release acceptance](v050-release-architecture.md#installed-release-acceptance)
for the refusal, rollback, and recovery contract.

Final publication requires a clean parser-pack construction on the exact main revision, successful package installation and CLI/MCP behavior checks, and supported predecessor upgrade and failure-recovery proof. The release workflow then verifies hosted metadata and installs the published assets. These checks do not authorize stable promotion.

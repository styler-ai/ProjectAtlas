# ProjectAtlas v0.4.5-rc1 release notes

ProjectAtlas v0.4.5-rc1 completes the local worktree-atlas workflow for agents while preserving the existing terminal dashboard and keeping Git lifecycle outside ProjectAtlas.

## Highlights

- Remain in one explicitly selected control checkout and address existing Git worktrees anywhere on the filesystem through short MCP aliases.
- Discover and register worktrees with `atlas_worktree_list` and `atlas_worktree_add`, initialize a registered target with `atlas_init(worktree=...)`, and retire only the ProjectAtlas registration with `atlas_worktree_remove`.
- Reuse a compatible complete control atlas through a private SQLite hydration candidate, then assign a new target identity, clear non-transferable state, reconcile exact branch and dirty bytes, and activate atomically. Existing valid target databases are preserved and unsuitable baselines fall back visibly to ordinary init.
- Keep every checkout's source graph, purposes, tasks, generation, and writes isolated while allowing explicit bounded read-only graph federation through ordered `worktrees` aliases with labels on every participant, result, blocker, coverage row, and continuation.
- Record alias-routed MCP token usage once in control, synchronize independent local aggregates monotonically, retain retired origins, and show repository-wide totals from the control CLI/MCP/TUI without changing the TUI layout. Exact worktree reports remain local.
- Ship the complete workflow in the version-matched ProjectAtlas skill, README, agent integration guide, worktree lifecycle guide, architecture views, GitHub Pages landing page, and one holistic cross-platform E2E.

## Compatibility and upgrade

Schema 18 is an append-only migration from the released schema. Existing graph, purpose, and telemetry rows remain authoritative; older runtimes refuse the newer schema rather than resetting or downgrading it. Single-root, non-Git, explicit `project_path`, ordinary CLI, and existing-database behavior remain supported.

The reserved alias `main` identifies the explicitly selected control atlas, not a branch or folder name. `worktree` and `project_path` are mutually exclusive on root-scoped MCP calls. A bare/common manager with zero or several active checkouts still requires an exact checkout selection.

## Deliberate boundaries

ProjectAtlas does not create, switch, move, prune, merge, or delete Git worktrees or branches. It does not introduce a shared writable source graph, a new worktree TUI, a background daemon, a new crate, or a dependency. The distributed/versioned released-main atlas for sharing a maintained baseline between machines or team members remains separate work in [issue #456](https://github.com/styler-ai/ProjectAtlas/issues/456).

## Verification policy

RC1 is published only after focused and full locked Rust gates, schema and fault coverage, the named holistic worktree E2E on Ubuntu, Windows, macOS Intel, and macOS ARM, installer and packaged-runtime checks, strict OpenSpec and IssueOps synchronization, rendered Mermaid inspection, and exact-head review resolution. It is a GitHub prerelease and does not replace the preceding stable GitHub Latest release.

For the complete workflow and failure semantics, see [Worktree atlas continuity](worktree-lifecycle.md). For architecture ownership and request flows, see [ProjectAtlas 3 Architecture](projectatlas-3-architecture.md#architecture-views).

# ProjectAtlas v0.4.5-rc2 release notes

ProjectAtlas v0.4.5-rc2 stabilizes the RC1 agent workflow across documentation
navigation, purpose mutation, terminal rendering, symbol publication, local
SQLite placement, and the complete worktree lifecycle.

## Highlights

- Start documentation traversal from the known Markdown file. The file now owns
  every canonical `documents` relation, target-inbound reads expose the same
  edge as `documented_by`, exact headings and occurrences remain evidence, and
  complete extraction with no supported static target reports trusted
  `no_candidates` coverage instead of an indistinguishable empty result.
- Keep the explicit token dashboard inside its captured terminal viewport. Full
  overview and trend layouts retain their established 80x50 and 80x30
  boundaries; smaller terminals receive a priority-ordered compact snapshot,
  wide graphemes occupy their real display width, and wide-but-short overviews
  skip the optional Atlas read.
- Admit purpose mutations through exact current saved-source freshness. Applied
  batches publish a changed source generation before conditional evaluation,
  retain one admission witness through the existing SQLite transaction, and
  perform one final detect-only witness before commit; stale, canceled, changed,
  or failed work rolls the entire batch back without changing purpose rows or
  authored revision.
- Omit malformed or oversized parser identities at the shared symbol-admission
  boundary instead of projecting declaration text into graph identity. C# field
  declarations retain their exact semantic field name across large initializer
  boundaries, valid siblings survive malformed declarations, and import-symbol
  compatibility remains intact.
- Open supported local SQLite databases on Linux Btrfs subvolumes even when the
  file device differs from the owning mount-inventory device. Exact placement
  remains the fast path; the exceptional fallback selects one deepest
  component-boundary ancestor and still refuses ambiguous, network, unknown, or
  changed placement before SQLite opens.
- Extend the mandatory worktree proof through unregister, Git removal, prune,
  recreation at the same path, new registration and project identity, safe
  purpose/graph hydration, telemetry isolation, scan/watch, and CLI/MCP routing.

## Compatibility and upgrade

Schema 18 remains the database contract. The graph-projection contract
fingerprint advances so an older RC1 projection receives one typed full refresh
before it can be served; authored purpose, project identity, and supported
released-database migration behavior remain intact. CLI, MCP, JSON, TOON,
single-root, non-Git, explicit-root, worktree-alias, and structured token-report
surfaces remain compatible.

## Deliberate boundaries

RC2 adds no crate, dependency, schema, background daemon, shared writable graph,
or ProjectAtlas-owned Git lifecycle operation. Invalid symbol identities are
omitted rather than truncated or hashed. Filesystem-placement fallback does not
bypass the existing local-filesystem allowlist or pre-open revalidation. Purpose
admission does not demote durable authored intent after later source edits.

## Verification policy

RC2 is published only after focused and full locked Rust gates, database fault
and concurrency coverage, a real Linux Btrfs subvolume CLI/MCP reopen, exact
compact/full terminal boundaries on supported platforms, the complete recreated
worktree lifecycle, installer and packaged-runtime checks, strict OpenSpec and
IssueOps synchronization, rendered Mermaid inspection, and exact-head review
resolution. It is a GitHub prerelease and does not replace the preceding stable
GitHub Latest release.

For the complete workflow and failure semantics, see
[Agent navigation](agent-navigation.md), [Worktree atlas continuity](worktree-lifecycle.md),
and [ProjectAtlas 3 Architecture](projectatlas-3-architecture.md#architecture-views).
